# Windows 节点部署进展（2026-09-05）

## 目标与技术路线

目标是让校园手机／平板通过校园 IPv6 连接校外节点，由节点访问 IPv4 互联网。校园端到节点必须使用 IPv6；节点到目标网站可以使用 IPv4。

```text
校园手机／平板代理客户端
    → 校园 Wi-Fi IPv6 加密连接
    → 校外 Windows 原生 sing-box
    → 校外 IPv4 出口
    → 互联网目标服务
```

仅让手机通过 IPv4 连接中转服务器不满足目标。只有 IPv4 的服务器不能单独承担 IPv6 入口。是否符合预期计费，需另做校园账户 A/B 验证。

## 已完成成果

- 已准备 Windows 原生 sing-box 安装、配置生成、本机测试、临时入站测试、激活和停止脚本；当前实现使用 Shadowsocks 2022。
- 本机加密 TCP、UDP DNS 和 IPv4 出口测试此前通过。
- 校园手机的 IPv6 测试截图显示通过；用户另反馈移动数据也支持 IPv6。
- 用户反馈同一 Wi-Fi 下可以访问临时测试页面，但校园网和移动数据访问失败。
- 最近一次检查时，节点 IPv6 默认路由走 WLAN，测试服务正常监听，本机 HTTP 测试正常。
- 检查了 Windows ActiveStore 中实际生效的临时规则：允许指定程序、WLAN、节点 IPv6 和测试 TCP 端口；适用于所有网络类型，远端范围为公网 IPv6 `2000::/3`，并非仅允许本地子网。
- 已启用的显式入站阻止规则中，未发现针对测试程序的规则。这不等于排除了所有第三方过滤组件。
- EasyConnect 曾导致路由器管理地址走 VPN；断开后管理页面恢复可达。此结果不证明公网 IPv6 入站已经恢复。

## 当前网络与阻塞点

节点连接中兴 G5TS 5G CPE，使用中国移动网络，固件为 `BD_ZXSTCNG5TSV1.0.0B14`。WAN IPv4 为私网地址，路由器及电脑获得了全球单播 IPv6 地址。

**当前阻塞点是外部 IPv6 入站尚未通过。正式代理未完成校园端验收，不能宣称部署可用或免计费。**

已查看的路由器页面包括端口过滤、系统安全、更多、端口转发和远程管理配置，尚未确认一个适用于此固件的 IPv6 入站放行入口。表单展示 IPv4 示例本身不足以证明不支持 IPv6；不能照搬其他品牌或型号的操作。

远程管理、WAN Ping、IPv4 NAT 和 DMZ 不是已经验证的解决办法。本次没有形成经过验证的路由器放行配置。

## 最小改动的下一步

1. 同步启动临时服务和抓包，明确记录手机网络类型、刷新时间及结果。
2. 若请求到达电脑，继续检查本机过滤、服务响应和回程路由；若未到达，重点核查路由器与上游网络，不把无响应直接等同于运营商封锁。
3. 若确认现有 5G 网络无法允许入站，优先换接可验证允许 IPv6 入站的网络，保留 Windows 和 sing-box，仅更新节点地址及相关配置。
4. 如需中转，必须保留手机可达的公网 IPv6 入口；这是备选架构，不是当前已完成成果。
5. 校园入站成功后才激活正式节点、导入手机客户端配置，再验证出口、UDP、稳定性和校园计费。

## 实现限制

- 浏览器测试链接只用于连通性验证，不是正式代理订阅或使用入口。
- 15 分钟是临时测试服务的期限，正式节点不受此期限限制。
- 当前自动启动依赖用户登录 Windows，不是登录前运行的系统服务；持续在线和休眠策略仍需验收。
- 尚未实现 DDNS。IPv6 地址变化后需更新规则和客户端，并重新验证。
- 当前路线采用 Windows 原生实现，不要求安装 Hyper-V；旧文档中的虚拟机路线仅作为其他环境的选项。
