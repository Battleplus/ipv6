# Windows 固定节点验证指南

目标是先确认公司网络中的 Windows 电脑能否作为公网 IPv6 服务端。以下步骤不要求提供密码，也不应公开完整 IP 地址。

## 0. 前置条件

- 已获得设备所有者和网络管理方对搭建个人对外服务的明确授权。
- 电脑可长期通电，已关闭自动睡眠，并有可接受的断电恢复方案。
- 校园端测试设备确实连接校园 Wi-Fi，并获得 IPv6。

## 1. 确认本机 IPv6

在 Windows PowerShell 中查看地址：

```powershell
Get-NetIPAddress -AddressFamily IPv6 |
  Where-Object { $_.IPAddress -notlike "fe80:*" } |
  Format-Table InterfaceAlias,IPAddress,PrefixLength,AddressState
```

应看到非 `fe80::/10` 的地址。`fe80::` 是链路本地地址，不能用于互联网访问。测试截图对外分享时至少遮住地址后半部分。

## 2. 判断地址是否稳定

重启电脑和路由设备后重复查看。若前缀或地址会变化，需要 IPv6 DDNS；不要在客户端长期写死临时隐私地址。

## 3. 建立临时测试端口

先只做短时、无敏感数据的连通性验证。可在获授权后由熟悉网络管理的人启动一个临时监听服务，并在 Windows Defender 防火墙中仅为该端口创建临时入站规则。

验证期间应遵循：

- 使用随机高位端口，不开放远程桌面、SMB、数据库等管理端口；
- 不关闭整个防火墙；
- 测试结束立即停止监听并删除临时规则；
- 不在公开页面发布完整 IPv6 地址。

## 4. 从校园网做真正的入站测试

使用校园 Wi-Fi 下的另一台设备连接该 Windows 公网 IPv6 和测试端口。不能使用同一公司网络内的设备代替，因为那无法证明互联网入站可达。

结果解释：

- 能连接：说明基础入站路径可用，可以进入虚拟机验证阶段。
- 超时：检查 Windows 防火墙、上级路由器 IPv6 防火墙、公司边界策略和运营商入站限制。
- 拒绝连接：通常表示路径已到主机，但没有服务监听或端口不一致。

## 5. Hyper-V 虚拟机验证

满足入站条件后，再启用 Hyper-V、创建 Ubuntu 虚拟机，并将网卡连接到“外部虚拟交换机”。在虚拟机内确认：

- 获得非链路本地 IPv6；
- 能访问 IPv4 和 IPv6 互联网；
- 校园端能够连接虚拟机的临时测试端口；
- Windows 主机与虚拟机防火墙均只开放必要端口。

如果虚拟机没有公网 IPv6，需检查交换机模式、局域网 IPv6 前缀下发和上级防火墙。不要通过关闭全部安全策略来规避问题。

## 6. 再决定是否部署

只有上述测试全部通过，才值得按照候选项目的最新官方文档部署 sing-box 等服务。首次部署应使用独立低权限环境、小流量测试，并保留一键停止服务和删除防火墙规则的回退路径。
